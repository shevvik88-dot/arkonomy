### 17. Календарь — сумма дня под датой (В ПРОЦЕССЕ, план готов, ждёт подтверждения)

```
Клетка дня в Level 1 grid остаётся с текущим цветным фоном (категория +
интенсивность, без изменений). Под числом дня — вторая строка: сумма дня
со знаком ("-$2305" для дня трат, "+$X" зелёным для дня с доходом, net >
0). Красным/белым по контрасту для расходного дня.

СТАТУС: превью на реальных данных уже показано и сверено с реальным
размером клетки (не гипотетическим) — 12 июля. Измеренный размер клетки:
41.6px (375px viewport, худший случай) / 43.7px (390px) / 49.4px (430px,
максимум). Двухстрочный контент по высоте влезает свободно; по ширине —
на грани для крупных сумм (4-значные типа "-$2211").

Предложено (ждёт финального "да" юзера):
1. Сокращение крупных сумм — НЕ "$2.3k" (точка почти не экономит место),
   а целые тысячи без десятичных: "$2211" → "$2k" при amount >= $1000.
2. Малые суммы ("-$5", "-$12") — без изменений, и так короткие.
3. Пустые дни (нет транзакций) — вторая строка не рендерится вообще, тот
   же принцип, что уже есть для цвета (нет данных → C.sep, без интенсивности).
4. Будущие дни — технически тот же принцип возможен, НО семантически это
   не "net" (futureByDay хранит один доминантный ожидаемый платёж, не
   сумму всех ожидаемых списаний, и уж точно не проекцию будущего дохода)
   — вторая строка на будущих днях будет ВСЕГДА красной, это не net,
   а просто "ожидается такое-то списание". Нужно явное решение юзера,
   устраивает ли эта смысловая разница или нужна другая трактовка.

Реализация не начата — ждёт подтверждения по пунктам 1 и 4 выше.
```

## 📌 Известные компромиссы (product trade-offs)

- **iOS-сборка не конвертирует Free → Pro вообще** — anti-steering фикс (Guideline
  3.1.3, 10 июля) убрал из iOS не только кнопку покупки, но и любое упоминание
  цены/слова "upgrade"/веба где-либо в приложении (UpgradeModal, Trial Expired
  Modal, Markets/Savings/Profile/Insights paywall-тексты). Это осознанная цена
  Варианта 3 (быстрое прохождение ревью без интеграции StoreKit/IAP) — iOS
  теперь чисто канал **удержания** уже оплативших на вебе юзеров, не канал
  **приобретения** новых. Компенсация — задача 11 (email) выше; долгосрочно —
  Вариант 1 (настоящий Apple IAP) из чеклиста, если конверсия через веб
  окажется недостаточной.
